## 二、身份连续性能否仅凭合法视觉历史建立

### 2.1 合法锚点(t=0)[S+设计]

- t=0 首帧里"柜顶那只碗 / 灶面那只碗"是**纯空间锚定**,不需要任何
  实例 ID——首帧是 planner 本可看见的观测(init step 0 图像,审计一)。
- 因此"bowl_cabinet(t0)"与"bowl_stove(t0)"两个**轨迹标签**的初始化
  只用了首帧,合法。

### 2.2 连续性跟踪 [R]

- 跟踪器:SAM3 服务器现成(toolkit segment 绑定同源客户端,
  `toolkit.py:45-47`);对重放帧流逐帧分割、按 IoU/最近邻关联,
  即得两条轨迹 → "柜顶碗现在在灶面"的关系事实。
- 风险:pick 期间碗入夹爪、短时遮挡/大位移,跟踪可能断链。
  **[R] DEV0 前置项 2**:对一次录制的交换前缀跑离线跟踪,断链率与
  重关联正确率量化;断链处的合法补救 = 动作先验(夹爪持有物 =
  被夹轨迹延续,这本身是 planner 可见的合法信息:工具调用与夹爪状态)。

### 2.3 非法来源排除清单(预注册排除条款)[S]

- 禁:obj_of_interest / bddl 实例 ID / sim 物体坐标 / check_success
  真值作为任何记忆臂(C2/C3/C4)的输入来源;
- 允许:重放帧(SAM3 分割)、dump_state 级 state(EEF/夹爪/名字)、
  前缀的动作流元数据(技能边界,planner 可见的同类信息);
- C4 typed-state 的压缩(如 `moved(bowl_from_cabinet, to=stove)`)
  必须能溯源到 2.2 的轨迹段,离线管线一次性生成后冻结(Stage D
  sidecar 冻结纪律)。

### 2.4 判定

**可行(条件=[R]×2)**:合法性框架全部 [S](锚点/排除/防火墙);
跟踪稳健性与物理残余阈值是 DEV0 的两项运行验证。**无 [X] 项。**

## 三、若 DEV0 验证失败的后备(如实)

- EEF 残差超阈值 → 前缀改为"两次对称 move_to 往返"(无接触),
  牺牲交换真实性换末态对称;或决策点定义放宽为"homing 后再静置
  N 步"(仿真物理稳定段)。
- 跟踪断链率高 → oracle 臂降级为"首锚+末段锚"两点式(仅当交换后
  碗仍在视野,空间关系可由当前帧+首帧推断);若两点式也不稳,则
  C3 上界不可信 → **任务资格 FAIL,STOP**(如实报告,不硬凑)。
